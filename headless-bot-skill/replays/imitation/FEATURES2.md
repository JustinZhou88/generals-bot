# 模仿学习候选步特征定义 v2(32 维)

由 `replays/imitation/extract2.js` 生成;下游推理必须按**完全相同**的逻辑实现。
v1 的 24 维(f1-f24)定义**一字不动**,见 `FEATURES.md`;本文件只描述 v2 的增量。

## 数据格式

- `dataset2.jsonl`(index.json 前 90% = 422 局)/ `heldout2.jsonl`(后 10% = 47 局),每行:
  `{g: 局id, t: 半回合, c: [[32 floats(3位小数)], ...], y: 所选候选下标}`
- 每行 `c` 的**末尾**恒为"不动"伪候选行:f25=1,其余 31 维全 0。
- 行数最多 65(真实候选 ≤64 + 伪候选 1)。

## 决策点(v2 改动)

- **真实决策点**:同 v1(目标玩家该半回合首个 move,执行前快照;所选不在候选集则丢弃)。y 指向真实候选。
- **空转决策点**(新增):目标玩家**首次 move 之后、最后 move 之前**(严格 first < t < last),凡该半回合无该玩家 move,生成决策点,`y = 伪候选下标(= c.length-1)`。快照取在该半回合**任何 move 执行前**(即上一 `game.update()` 之后、处理该半回合 moves 之前)。合法步为 0 则跳过。受同一 CAP=800 与 `isOver()` 约束。
- **伪候选**:每个决策点(真实+空转)的候选集末尾追加,不参与 64 截断的采样,始终保留。
- **64 截断**:真实候选 >64 时下采样至 64(保持原扫描顺序),rng 同 v1(mulberry32(fnv1a(局id)),按局单流)。真实点 = 保留高手所选 + 随机 63;空转点 = 随机 64。注意:空转点也消耗 rng,故截断局面的采样子集与 v1 不逐点一致(仍完全可复现)。
- **"上一步"**(f27/f28 用)= 该玩家最近一次**真实** move `{start, end, turn}`,跨半回合追踪(含同半回合内的重复排队 move,取最近处理的一条);空转不更新;局首为空。
- **已知敌将记忆**(f12/f29 用)同 v1 规则("任一决策点上可见即永久记住"),但 v2 的决策点包含空转点,故记忆可能比 v1 更早建立(实测仅影响极少数点的 f12)。

## 追加特征(f25-f32;记号同 v1:srcArmy/destArmy 为高手视角,turn = 半回合)

| # | 定义 |
|---|---|
| f25 | 伪候选(不动)= 1;真实候选 = 0。伪候选行其余 31 维全 0 |
| f26 | dest 是已知城 ? `clip((srcArmy - 1 - destArmy)/40, -1, 1)` : 0("吃得动城"信号) |
| f27 | 链式推进:`src == 上一步.end` 且 `turn - 上一步.turn <= 2`(2 个半回合内)? 1 : 0 |
| f28 | 折返:`src == 上一步.end` 且 `dest == 上一步.start` ? 1 : 0(无时间窗) |
| f29 | dest 是敌格(f6=1)? f12 : 0(朝已知敌将 +1 / 背离 -1 / 未知或等距 0) |
| f30 | dest 是已知城 **且** 城属敌方(`terrain[dest] >= 0 && != me`)? 1 : 0 |
| f31 | dest 是敌格 且 `srcArmy - 1 > destArmy`(能吃)? 1 : 0 |
| f32 | `(turn % 50 >= 30 ? 1 : 0)`(= f14)× dest 是敌格(= f6) |

所有值四舍五入到 3 位小数。f25-f32 实测取值范围 [-1, 1]。
